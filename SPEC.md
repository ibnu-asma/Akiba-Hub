# A2SV Hub — Product Specification (Consolidated)

> **Status:** Requirements consolidated for all three roles — **Student**, **Head of Education (HoE)**, **Head of Academy (HoA)** — from role documentation, app screenshots, and image-level UI descriptions.

## 1. Product overview

A2SV Hub is the internal education platform for A2SV. It is **invite-only**: the only entry into the platform is an invitation generated by a Head of Academy. Inside, the platform supports the full education loop:

- **Identity & invitations** — mass-invite and take-over invite flows; “Register Invite” onboarding form; role assignment.
- **Content authoring** — sessions (with location, meeting/resource/recording links), problems, tracks (5 phases), contests, daily problems.
- **Solving & submissions** — problem catalog on the Hub, external judges (LeetCode, Codeforces, HackerRank), manual submission form, A2SV Companion extension (Push Last Submission).
- **Accounting & reporting** — attendance with statuses + check-in/out, consistency, track completions, exercises matrix, contest performance, divisions, group comparison, reports.
- **Administration** — groups & supergroups, roles, audit log, stipends & funds (in-person HoE).

### Aggregation model (the key concept)

The dashboard is the *same feature family* rendered at three scopes:

| Scope | Viewer | Data window |
|---|---|---|
| **Self** | Student | exactly one student |
| **Group** | Head of Education | the students of the group(s) assigned to the HoE |
| **SuperGroup** | Head of Academy | all students across all groups of the supergroup |

System-scoped. Group Comparison + Repeated.

## 2. Access hierarchy

```
SuperGroup                        e.g. “Remote”, “InPerson”, “Rogue”
 \\- Group                       class, e.g. “Remote Group 5A” / “G5A”
     |- Track (phase from the 5)    Python / Phase I / Camp I / Phase II / Camp II
     |- Head(s) of Education        assigned to the group
     \\- Students                   enrolled in the group
```

- **Tracks** and **Daily Problems** are declared **per SuperGroup**.
- **Groups** belong to a SuperGroup; **Sessions** Events attend into groups; attendance records are per group/session.

## 4. Global design system

- **Palette:** white backgrounds; **A2SV green** primary `#00B366` (approx) with darker on hover; success green; danger red (delete rings); amber warning; muted grey for helper/secondary text.
- **Cards & surfaces:** white cards, soft rounded corners, subtle shadow, 1px hairline border.
- **Forms:** floating labels or clear bordered inputs; helper text in muted grey (e.g. “Short name (e.g., G5A)”); red inline validation; single submit disabled until valid.
- **Layout — three zones:**
  - **Global sidebar (left):** collapsible, split into **role sections with role-label headers** (e.g. “🎓 Head of Education”). Section visibility scales with role: **Student sees 1 section** (student nav only) · **HoE sees 2 sections** (student + “Head of Education”) · **HoA sees 3 sections** (all). Thin horizontal dividers separate sections; **Forum** lives in a shared section reachable by all.
  - **Top utility bar (right-aligned):** search, AI-assist (sparkle), notifications bell with red unread badge, avatar + green online dot. Consistent across all roles.
  - **Reporting sub-nav (horizontal):** appears only on HoE/HoA reporting pages — `Summary · Attendance · Consistency · Completion · Exercise · Upsolving · Divisions` with thin grey vertical separators.
  - **Active state:** selected nav item gets a very light green background with **bold A2SV-green text/icon**.
  - **Group Switcher:** on Reporting pages a dropdown sits top-right of the content area (e.g. “G4 + G5 InPerson”) and re-scopes all data on the page to the selected subset.
- **Floating button:** persistent bottom-right round FAB (sliders icon) on Dashboard / Super Groups pages.
- **Data visuals:** sparklines in stat cards (green/blue/orange), progress bars, donut/ring gauges, multi-series line chart (Mon–Sun, weeks as series), color-coded calendars, matrices, trophy icons (gold/silver/bronze) in comparisons, avatar stacks with count badges.
- **Status color semantics (lock these):** 🟢 **green** = success / solved / present · 🔴 **red** = absent / unsolved · 🟠 **orange** & 🟡 **yellow** = excused / in-progress · 🔵 **blue** = late / informational.
- **Conventions:** tooltips on icon buttons, breadcrumb on detail pages, relative timestamps (“9d”), role badges (`Head`, `Student`), green cards in audit log.

## 5. Onboarding — Register Invite (pre-role)

The consumer side of an invitation generated by the HoA.

- Header: HUB logo + “Register Invite” title.
- Avatar upload: circular, “Update photo”, jpeg/jpg/png/gif, max **3.1 MB**.
- Two-column form:
  - **Required:** Name*, Password*, Country* (dropdown, e.g. Ethiopia), University*, Email* (pre-filled from invite, e.g. `geleta.daba@a2sv.org`).
  - **Optional:** Department, Instagram username, LinkedIn URL (validated `linkedin.com/in/...`), Student ID, Short bio.
- Inline red validation (“name is required”, “Invalid linkedin profile url”).
- Submit → account created with the role attached to the invite token.

On judge sites (LeetCode/Codeforces), a dark floating toolbar: A2SV badge, Run, Submit (+ count), **Push Last Submission** (primary), alarm/timer icon, notes icon. Student enters only time-spent and pushes — auto-logs the submission to the Hub without the manual form.

### 6.6 Profile → Consistency & Attendance

- **Attendance grid:** dense date cells colored green/yellow/red with check-in timestamp under dates (e.g. “2:28 PM”), “Show detail” toggle.

### 6.7 Forum

- Filter dropdown (“Filter post…”) + sort dropdown (Latest / Top / Oldest).
- Post cards: author avatar, name, “14 Mar 2024 7:35 PM”, bold title, body preview, up/down arrows + score, comments count, “Write A Comment”.

### 6.8 Contests
- Contest header (name, “Standing” badge/link, date) + problems A–E as standard problem cards.

### 6.9 Tracks / Exercises / Roadmap / Groups & Users

## 7. Head of Education role

### 7.1 Layout
- HoE nav shows **2 sections** (Student + “🎓 Head of Education”, per §4). The HoE section is creation-and-monitoring oriented, each item with an icon:
  - **Dashboard** (🛹 skateboard icon) — group stats landing.
  - **Take attendance** (📅 calendar icon) — roster to mark presence.
  - **Add problem / Add track / Add contest / Add exercise** (➕ plus icons) — content forms.
  - **Add Session** (thinner plus icon) — scheduling tool.
  - **Daily problem** (📅 list icon) — daily queue management.
  - **Stipend & Funds** (💰 money-bag icon) — **in-person HoE only**.
  - **Summary** — top-level reporting hub with the horizontal sub-nav; **Groups & Users**; **Forum**.
- Reporting pages carry the horizontal **Summary sub-nav** (lines tracked by the Group Switcher at top-right, e.g. “Group G4 + G5 InPerson”).

### 7.2 Dashboard (group-scope widgets)

Same family as §6.2 but aggregated for the HoE’s group(s):
- **Quote banner (group-specific):** “Persistence is very important…” — Elon Musk.
- **Stat cards (Group health):**
  - **Team Solutions** — total problems solved by the group.
  - **Team Time Spent** — total minutes, auto-converted to **Days**.
  - **Rating** — average group contest rating.
- **Daily Solve widget** — donut chart `Solved X / Total` (e.g. `12/20`) for the current day + avatar list of the students who solved it.
- **Problem-Solving chart** — high-end 4-series visualization (**Week 1–4**, color-coded) plotted against Mon–Sun to compare activity trends over the month.

### 7.3 Create Session (screenshots confirmed)

- **Schedule:** Date (calendar picker) + Start/End time with quick duration presets (e.g. `8:00 PM – 11:00 PM`, “+1h”).
- **Details:** Name, Description, Location, Lecturer, **Groups** (multi-select).
- **Links:** **Resource link** (slides/materials) and **Recording link** (Zoom/class captures).
- **Integration:** **Fund** dropdown (link the session to a budget) and **“Send Calendar invites”** toggle (via connected Google account).
- Sessions surface in the Events widget and are the parent for attendance.

### 7.4 Take Attendance

- Page/flow: pick a created session → a simple **roster list** of the group’s students, four status actions each:
  - **✓ (green) Present**, **X (red) Absent**, **O (orange) Excused**, **L (blue) Late**.
  - Includes an **“Everyone Present”** quick action.
- Exactly one status per student per session; check-in/check-out times captured.
- Rendering: color-coded monthly grid (green/yellow/red/etc.) for all students at a glance, with a “Show detail” toggle (mirrors the Student profile but group-wide).

### 7.5 Add Problem

Fields: **Name**, **Tags**, **Source** (platform), **Difficulty**, **Track** (optional), **Contest** (optional), **Link**. A **sparkle (AI) icon** near the Link field suggests auto-fetching problem metadata from the judge URL. Problems become visible to group students; editing/deletion allowed (trash icon) — students only get read + New Solution.

### 7.6 Add Track (per SuperGroup)

- UI is split into **Create / Delete tabs** — Create names the track and assigns it to a **Super Group** (e.g. “Remote”); Delete removes an existing one.
- Phase naming is one of the 5: **Python Track / Education Phase I / Camp I / Education Phase II / Camp II**.
- Bulk management utility: **“Reassign Problem(s) to Track”.**

### 7.7 Add Contest

- Contest types: **Standard** and **Super** contests (cross-group).
- **“Unrated” checkbox** — enables virtual participation without affecting ranks/ratings.
- Per contest: name, date, external “Standing” link, and problems A–E each with “New Solution”/“Open” controls; used for the Upsolving summary.

### 7.8 Add Exercise

- Exercise authoring mirrors Add Problem; lives within the Tracks/Exercises tree (per SuperGroup), the same set students consume in the Exercises page.

### 7.9 Daily Problem

- Queue-management UI: HoE **selects a Super Group**, **picks problems** into the daily queue, then uses a **“Save Order”** button to persist the daily schedule. Feeds the student daily-problem card (24h refresh).

### 7.10 Summary reporting hub (screenshots confirmed — the HoE “command center”)

A top-level **Summary** page with a **7-item horizontal sub-nav** — the **Summary** page itself + the 6 data tabs below (the doc’s “7 sub-tabs/views” = Summary + 6 tabs). All scoped by the Group Switcher.

1. **Attendance** — dense color-coded monthly calendar grid showing the group’s whole month at a glance; derived from attendance records (P/A/E/L) across sessions; a summary header shows totals (e.g. “Present: 4568 (82%)”); per-student percentage sorted by rate. Colors: **green = Present, red = Absent, yellow = Excused**.
2. **Consistency** — per-student daily solve counts (Hub + external judges like LeetCode), i.e. the group heatmap — each cell = **number of problems solved on that date**.
3. **Completion** — **vertical progress bars** per student through their assigned **Track** (phases), showing **% solved + Available remaining** in the track.
4. **Exercise** — matrix: **problems as columns, students as rows**, each cell `[Attempts] | [Time spent]` (e.g. `2 | 14m`); **green background = solved** (submissions include code / time / attempts for collaborative learning).
5. **Upsolving** — same matrix pattern scoped to **contest problems (A–B–C…)** per contest, tracking who finished problems after the live event (incl. virtual); attempts + time.
6. **Divisions** — list view grouping students into **Div 1, Div 2, …** derived from cumulative contest performance. *(Rule TBD — auto thresholds vs manual.)*

### 7.11 Group Comparison (BETA)

- On the **homepage** (scroll to section): right-side dropdown to multi-select groups, mode **Table / Graph**, range **Past week → All time**.
- Confirmed modes (**Competitive Leaderboard** vs other groups): **Summary, Attendance, Consistency, Track Completion, Contest Performance**.
- **Consistency** table compares **Average / Min / Max Consistency**, **Average Daily Solves per student**, and **Total Expected vs Actual solves** (accountability metric).
- Ranking: **Gold, Silver, Bronze trophy icons** for the top-3 groups; feeds the dashboard **State: Good/Okay/Bad** gauge.

### 7.12 Stipend & Funds (in-person HoE only)

- **Fund table:** student rows with **checkboxes** to approve payments.
- **Toggles:** **“Weekly Attendance Mode”** (auto-calculates payout from attendance) and **“Unpaid only”** (filter).
- **Add Fund form:** Name, Description, **Amount**, **Currency** (e.g. Ethiopian Birr).
- Exact calculation formula TBD (§13 open questions).

### 7.13 Latest Submissions (feed)

- Group-wide real-time feed of submissions, sorted by submission time (student, problem, time).

### 8.5 Generate Invitation

Two paths toggled by a **Mass Invite checkbox**:

- **Mass Invite ✅ (new person):** select **Role** (dropdown lists: Community, Executive, Head of Academy, Head, Student) → **email text area** (multiple emails, e.g. `EXAMPLE@a2sv.org`) → Submit.
- **Mass Invite ❌ (existing user):** select **Role** → **“(Optional) Select take-over user”** dropdown (re-assign an existing account a new invite/role) → Submit.
- Invitations are the **only** registration path; send via email.

### 8.6 Groups (Add Group)

Form: **Name*** (e.g. “Remote Group 5A”), **Short name*** (e.g. “G5A”), **Description** (textarea), **Assign Head of academics*** (dropdown linking HoE/HoA), **Country***. Delete section at page bottom: **Select group** dropdown + **Delete** button.

### 8.7 Roles

- Form: **Select user** (searchable dropdown, e.g. “Abdellah Kamil”) → **Select role** → **Select group** (re-assign class) → Submit. Covers promotions and demotions (student ↔ HoE ↔ HoA) and group transfers.
- **Delete user** section: select user → **Delete** (soft-delete; HoA can view previously removed people).

### 8.8 Recent Actions (audit log)

- Chronological feed of everything happening in the academy.
- Item = green card with a **checkmark icon**: **actor avatar + name**, **role badge** (e.g. “Head”), **action type** (e.g. “CREATE”, “DELETE”), **timestamp** (“02 Oct 2024 9:17 AM”), plus a descriptive sentence — *“Fikreselassie Solomon Mulu created an event called ‘A2SV <> Remote G5E Camp II : Practice Session’”* — with **links** to the created object (Session / Problem / Contest).
- Logged actions include: create/delete session, add problem, add/delete contest, add/delete track, add/delete group.

### 8.9 Reports

- Page showing performance of the groups/supergroup(s): **absentees** and **time dedicated to problem solving** (extend to the full summary metrics §7.10 when needed).

### 8.10 Group Comparison (shared spec)

- Homepage section; right-side dropdown to multi-select **groups**; mode **Table | Graph**; range **Past week | All time** (since group creation).
- **Modes & metrics:**
  1. **Summary —** consistency %, track completion, real attendance, total attendance, submission count, contest rating.
  2. **Attendance —** Real (present only), Total (present + excused), #Presents, #Excused, #Absent (no notice), Check-in/Check-out ratio.
  3. **Contest conversion —** % and ratio of problems solved in A2SV-facilitated contests.
  4. **Track completion —** avg completion/group, avg exercises solved/student, completion %, min/max completion %, students who completed *all* problems.
  5. **Consistency —** avg consistency, min/max, avg daily solves/student, total **expected** solves, **actual** solves.
- Trophy ranking (Gold/Silver/Bronze) for league-table display.

}

interface Contest {
  id; name; number?; type: 'standard'|'super'; unrated: boolean;

}
interface ContestProblem { contestId; pseudo: 'A'|'B'|'C'|...; problemId; }

interface Session {
  id; name; description?; date; startTime; endTime; durationPreset?;
  groupIds: string[]; location?; resourceLink?; recordingLink?; lecturer?;

interface Submission {

}

  action: 'CREATE'|'UPDATE'|'DELETE'; entityType; entityId; description; // human sentence
  createdAt;
}

interface Post { id; userId; title; body; createdAt; votes; comments: Comment[]; }

// Between them: Division (id, name e.g. “Div 1”, threshold rating), expected-solve config,

## 12. Cross-cutting invariants

1. **Invite-only registration.** No open signup; identities come from HoA invitations only.
2. **Every admin writes → `ActivityLog`.** Session/problem/contest/track/group CRUD (plus role changes + stipend distribution) appended to Recent Actions.
3. **Soft delete for users.** Deleted users move to the “removed users” list HoA can inspect; no cascade hard delete.
4. **Scope enforcement.** 3-level visibility (self / group / supergroup); comparisons and summaries never leak across supergroups for HoE.
5. **Time stored in minutes**; displayed as days on dashboards (minutes → days conversion util).
6. **Daily problem semantics:** 24h refresh; one active problem per SuperGroup per date; daily-solve metric = distinct students with ≥1 submission that date.
7. **Calendar invites are a flag** — session write triggers external calendar sync when `calendarInvite` is on.
8. **Upsolving vs live:** contests track rating impact; `unrated` contests list virtual participants without rating writes.
